# Cinema Booking

Веб-приложение для просмотра расписания кинотеатра и онлайн-бронирования билетов.

Проект разработан в рамках дипломной работы по программе **«Веб-разработчик: Backend-разработка на Python»** в Нетологии.

## О проекте

Приложение состоит из двух частей:

* публичной части для посетителей кинотеатра;
* административной части для управления залами, фильмами, ценами и расписанием.

Посетитель может посмотреть доступные фильмы и сеансы, выбрать место в кинозале и забронировать билет.

Администратор может управлять залами, местами, фильмами, ценами и расписанием сеансов.

## Основные сущности

В приложении реализованы следующие сущности:

* **Кинозал** — название, количество рядов, количество мест в ряду и цены.
* **Зрительское место** — ряд, номер и тип места: обычное, VIP или недоступное.
* **Фильм** — название, описание, длительность и возрастной рейтинг.
* **Сеанс** — фильм, зал, дата и время начала.
* **Бронирование** — данные посетителя и связанные билеты.
* **Билет** — сеанс, место, стоимость, уникальный код и QR-код.
* **Пользователь** — администратор системы и неавторизованный посетитель.

## Возможности посетителя

* просмотр списка фильмов;
* просмотр расписания сеансов;
* выбор конкретного сеанса;
* просмотр схемы зрительских мест;
* просмотр занятых и свободных мест;
* выбор места;
* бронирование билета;
* получение уникального кода бронирования;
* просмотр билета с QR-кодом.

## Возможности администратора

Административная часть содержит разделы для:

* управления кинозалами;
* создания залов;
* настройки мест в зале;
* изменения типа места;
* настройки цен обычных и VIP-мест;
* управления фильмами;
* формирования расписания сеансов;
* выбора даты для настройки расписания;
* просмотра расписания в виде временной сетки;
* авторизации администратора.

Администраторская авторизация выполняется с использованием Django-аутентификации и токенов DRF.

## Валидация и ограничения

Основные проверки выполняются на стороне сервера.

Реализованы:

* запрет бронирования уже занятого места;
* проверка принадлежности места залу выбранного сеанса;
* запрет повторного бронирования одного места на один сеанс;
* запрет пересечения сеансов в одном кинозале;
* уникальность кода бронирования;
* уникальность кода билета;
* серверная валидация данных через Django REST Framework.

Пароли пользователей обрабатываются стандартными средствами Django и хранятся в хешированном виде.

## QR-коды

Для каждого билета создаётся QR-код.

Билет связан с:

* конкретным сеансом;
* конкретным рядом;
* конкретным местом;
* уникальным кодом билета.

## API

Основные API-эндпоинты:

```text
GET    /api/movies/
GET    /api/movies/<id>/

GET    /api/halls/
POST   /api/halls/
GET    /api/halls/<id>/
PATCH  /api/halls/<id>/
DELETE /api/halls/<id>/

GET    /api/seats/
GET    /api/seats/<id>/
PATCH  /api/seats/<id>/
DELETE /api/seats/<id>/

GET    /api/sessions/
POST   /api/sessions/
GET    /api/sessions/<id>/
PATCH  /api/sessions/<id>/
DELETE /api/sessions/<id>/

GET    /api/sessions/<id>/seats/

POST   /api/admin/login/
```

API бронирования используется публичной частью приложения.

## Административная авторизация

Для входа администратора используется endpoint:

```text
POST /api/admin/login/
```

После успешной аутентификации сервер возвращает токен.

Frontend сохраняет токен и использует его при обращении к защищённым административным API.

Изменение данных через API разрешено только авторизованному администратору.

## Тестирование

Для проекта реализированы автоматические тесты backend-логики.

Запуск тестов бронирования:

```bash
python manage.py test bookings
```

Запуск тестов кинотеатра:

```bash
python manage.py test cinema
```

Полный запуск:

```bash
python manage.py test
```

Проверяются, в частности:

* создание бронирования;
* повторное бронирование занятого места;
* выбор места из другого зала;
* расчёт стоимости VIP-билета;
* бронирование нескольких мест;
* генерация кода билета;
* генерация QR-кода;
* атомарность бронирования;
* пересечение сеансов;
* изменение типа места;
* отключение места;
* изменение цен зала.
